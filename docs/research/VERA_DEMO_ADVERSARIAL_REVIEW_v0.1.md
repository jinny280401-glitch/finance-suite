# VERA_DEMO_ADVERSARIAL_REVIEW v0.1

**角色：** Adversarial Reviewer — 专找 Demo 会被评委误解、忽略、或觉得"不过如此"的地方
**审查对象：** Synthesis Part 4 的三个 Demo 设计
**审查维度：**
1. 5 秒第一眼是否懂价值（"这东西帮我省时间了"）
2. 是否区别于 ChatGPT（"这不是换个 UI 的 AI 聊天"）
3. 是否符合金融用户真实工作流（"我真的会这样用吗"）
4. 是否会被评委误解能力边界（"他们是不是在吹牛"）

**禁止：** 提新功能。只审现有 Demo 设计的弱点 + 修正建议。

---

## Demo 1: 一分钟公司研究卡

### 综合评分

| 维度 | 评分 | 说明 |
|---|---|---|
| 5 秒第一眼 | ⚠️ 3/5 | 内容好，但信任差异化在 5 秒内不可见 |
| 区别于 ChatGPT | ⚠️ 3/5 | 看起来像"格式更好的 AI 摘要" |
| 金融工作流 | ✅ 4/5 | 3 条变化 + 证据 + 风险 = 真实分析师的工作方式 |
| 能力边界清晰 | ✅ 4/5 | Run ID + 证据计数 + 审查状态，边界表达好 |

### 致命弱点：信任在底部，5 秒看不见

当前设计：

```
贵州茅台 · 最近变化
━━━━━━━━━━━━━━━━━━━━━
变化 1：营收增速放缓          ← 用户先看到内容
  事实：...
  证据：...
  审查：✓ ✓ ✓               ← 信任标记在第 6 行才出现

变化 2：批价企稳回升
  ...

变化 3：分红政策调整
  ...

━━━━━━━━━━━━━━━━━━━━━
本次研究：Run #... · 证据 7 条  ← 信任总结在最底部
```

**问题：** 用户 5 秒内看到的是"营收增速放缓 9.2%"，和 ChatGPT 输出没区别。Trust badge（✓ Citation ✓ Freshness）在第 6 行才出现。底部的信任总结大概率被跳过。

**修正：信任前置**

```
贵州茅台 · 研究卡
━━━━━━━━━━━━━━━━━━━━━
✅ 7 条证据 · 3 条主张 · 全部通过审查    ← 信任总结放第一行
━━━━━━━━━━━━━━━━━━━━━

变化 1：营收增速放缓
  9.2%（去年同期 16.7%）                ← 数字先出
  [2026 半年报 第 12 页] →               ← 来源紧跟
  风险：消费复苏不确定性

变化 2：批价企稳回升
  ¥2,350 → ¥2,520
  [今日酒价 08-03] →
  ⚠️ 部分地区仍低于 ¥2,400 [XX]         ← 冲突证据在同一条里

变化 3：分红比例调整
  51.9% → 60%
  [董事会公告 07-28] →

━━━━━━━━━━━━━━━━━━━━━
Run #20260803-001 · 可追溯 · 可质疑
```

**改动：** 三条——
1. 信任总结放顶部而非底部
2. 来源链接紧跟每个数字（不另起一行）
3. 冲突证据直接标注在数据旁边，不放到底部备注

### 第二个弱点：没有"时间节省"的感知锚点

用户看到研究卡，不会主动想"这帮我省了多少时间"。需要一个参照物。

**修正：加一个对比行**

```
⏱ 本次研究耗时：47 秒
📄 等效人工工作量：阅读 3 份公告 + 2 个数据源 ≈ 15-25 分钟
```

这不是精确数字，是感知锚点。评委看到 47 秒 vs 25 分钟，立刻懂了价值。

## Demo 2: AI 研究质检员

### 综合评分

| 维度 | 评分 | 说明 |
|---|---|---|
| 5 秒第一眼 | ✅ 5/5 | 对比式展示（普通 AI vs Vera）天然抓注意力 |
| 区别于 ChatGPT | ✅ 5/5 | 这一点做到极致——拒绝不是无能，是专业 |
| 金融工作流 | ⚠️ 3/5 | "拒答"后缺下一步行动指引 |
| 能力边界清晰 | ⚠️ 3/5 | 可能被理解为"什么都不会就说不能判断" |

### 致命弱点：拒答后像"死胡同"

当前设计：

```
审查结果：❌ 无法发布
问题主张："公司未来增长确定"
Citation Gate：❌
...
建议：将主张改为"过去 3 年营收复合增长率 12.3%"
```

**问题：** "建议改为..."看起来像文字润色建议，不够强。评委可能觉得："所以 AI 就是让换一种说法？"

**修正：拒绝 → 证据缺口 → 补证路径**

```
━━━━━━━━━━━━━━━━━━━━━
⚠️ 暂不发布：证据不足
━━━━━━━━━━━━━━━━━━━━━

原始问题："茅台未来能买吗？"

✗ 无法回答的部分：
  "能买吗" —— 这是投资建议，Vera 不回答投资建议
  "未来" —— 当前证据不支持预测

✓ 当前可以回答的部分（基于已有证据）：
  ✓ 过去 3 年营收复合增长率 12.3%    [年报]
  ✓ 管理层指引 2026 年增长 8-12%     [业绩说明会]
  ✓ 当前 PE 处于近 5 年 30% 分位    [Wind]

🔍 如需更完整分析，建议补充：
  □ 同行对比数据（可选 3-5 家可比公司）
  □ 最新卖方一致预期
  □ 行业增速基准

━━━━━━━━━━━━━━━━━━━━━
这不是"无法判断"。这是"基于当前证据，这里是可以说的，这里是不能说的，想多说需要这些。"
━━━━━━━━━━━━━━━━━━━━━
```

**改动：** 三条——
1. "暂不发布"替代"无法发布"——语义从"能力不够"变成"证据不够"
2. 拆分"不能回答"和"可以回答"——拒绝是有限拒绝，不是全盘否定
3. 给出"补证清单"——展示下一步，拒绝不是终点

### 第二个弱点：对比对象太弱，像 strawman

"普通 AI：公司未来增长确定"——如果评委用的是 ChatGPT Pro，可能不会说这么 naive 的话。

**修正：对比对象具体化**

不要写"普通 AI"。写：

```
同样的问题，同样的数据输入：

通用大模型输出：
  "贵州茅台作为白酒龙头，品牌壁垒深厚，未来增长前景确定，建议长期持有。"
  ↑ 2 个未支持主张、1 个投资建议、0 个来源

Vera 输出：
  [展示上面的结构化结果]
```

这样评委可以对标自己用的 ChatGPT，觉得"确实，ChatGPT 就是这么回答的"。

## Demo 3: 研究过程透明工作台

### 综合评分

| 维度 | 评分 | 说明 |
|---|---|---|
| 5 秒第一眼 | ❌ 2/5 | 看起来像 CI/CD pipeline |
| 区别于 ChatGPT | ⚠️ 3/5 | 工程感太重，不像金融产品 |
| 金融工作流 | ⚠️ 3/5 | 步骤命名是工程师思维 |
| 能力边界清晰 | ⚠️ 3/5 | 边界被工程术语掩盖了 |

### 致命弱点：看起来像 DevOps 仪表盘，不像研究工具

当前设计的 ASCII 流程图：

```
┌─ 研究问题 ──────────────────┐
│ → Brief Rewriter: 拆解为 3 个子任务 │
├─ 证据采集 ──────────────────┤
│ ✓ 财报数据     来源：上交所    │
│ ⚠️ 券商研报    原因：非一手    │
├─ Trust Gate 审查 ───────────┤
│ ✓ Citation ✓ Freshness ...  │
```

**问题：** 金融评委看到的是 "tech pipeline"，不是"研究过程"。Brief Rewriter、Evidence Collector、Claim Builder 是内部架构术语，不应该暴露给用户。

**修正：翻译成用户语言**

```
贵州茅台 · 研究过程

📋 拆解问题                    ← 不是"Brief Rewriter"
   "茅台最近变化" → 营收、渠道、分红 三个方向

📊 采集数据                    ← 不是"Evidence Collector"
   找到 12 条相关数据
   采用 7 条（直接相关 + 权威来源）
   舍弃 2 条券商研报（非一手信息）
   舍弃 3 条（数据过时）

🔍 逐条核验                    ← 不是"Trust Gates"
   ✓ 每条数据有出处 —— 7/7 通过
   ✓ 数据在有效期内 —— 7/7 通过
   ✓ 数字计算正确 —— 3/3 通过
   ⚠️ 批价存在区域差异 —— 已标注

👀 独立审查                    ← 不是"Adversarial Reviewer"
   审查 AI 发现：批价区域差异值得单独标注
   → 已采纳

✋ 人工确认                    ← 不是"Human Approval"
   [3 条主张 + 审查结果] → 确认发布

📤 输出
   研究卡 + 7 条证据 + 完整审查记录
```

### 第二个弱点：评委看不出"为什么要给我看这个"

Demo 3 最大的风险：评委觉得"这就是个流程图，又不需要我操作"。

**修正：加一个交互点**

不是展示静态图。而是：

> "现在，假如你想质疑'批价企稳回升'这条主张——点击证据链接，你会看到原始数据。如果你发现数据有问题，可以在这里标记'存疑'——这条主张会被退回到证据采集环节，重新验证。"

给评委一个"我也能参与"的代入感。否则 Demo 3 就只是架构图。

## 跨 Demo 的综合风险

### 风险 1：三个 Demo 展示的是"三个产品"还是"一个产品"？

当前设计：Demo 2 是质检界面，Demo 1 是研究卡，Demo 3 是工作台。三个看起来像三个独立产品。

**建议：** 统一视觉语言。同一个顶栏、同一个状态标识系统（✓ ⚠️ ❌）、同一个"Run #"追溯体系。让评委感知"这是一个产品的三个使用场景"，不是"三个 demo"。

### 风险 2："拒绝"叙事过度

如果 Demo 2（质检员）占时太长，评委可能形成"这 AI 什么都不会，只会说不能判断"的印象。

**建议：** Demo 2 控制在 45 秒内。紧接着 Demo 1 展示"拒绝不是常态——当证据充足时，47 秒出一张研究卡"。先拒绝再产出的节奏必须在 2 分钟内完成。

### 风险 3：缺少"谁在用"的真实感

所有 Demo 都是虚构的茅台案例。评委潜意识会觉得"这是 demo 数据，真实场景不一定这样"。

**建议：** 如果一个 Demo 能用真实数据（比赛当天或前一天的真实公告 + 真实行情），说服力翻倍。至少 Demo 1 应该用真实数据。

## 修正后的 Demo 优先级

| Demo | 修正后定位 | 时间 | 开场句 |
|---|---|---|---|
| Demo 2 | "为什么 ChatGPT 不够"——对比冲击 | 45s | "同样的问题，同样的数据。大家看区别。" |
| Demo 1 | "Vera 能做什么"——正面能力展示 | 60s | "当证据充足时，47 秒完成一个分析师 25 分钟的工作。" |
| Demo 3 | "怎么做到的"——如果评委追问 | 60s | "这不是 prompt engineering。每一步都可追溯、可质疑。" |

## Adversarial Verdict

**建议修改后 APPROVED。**

三个 Demo 的方向正确。当前版本的弱点集中在：
1. 信任标记位置不对（放底部没人看）
2. 拒绝后缺补证路径（像死胡同）
3. 架构术语泄露到用户界面（听起来像开发者工具）
4. 缺少"时间节省"感知锚点和"真实数据"说服力

以上修正不改架构、不改功能、不改 Governance。只改表达层。可以在 Demo 构建时一并修正。
