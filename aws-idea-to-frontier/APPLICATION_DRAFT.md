## 1️⃣ 产品信息 (Product Information)

### 产品名称
**Vera** — 面向金融行业的可信 AI Research Runtime

### 一句话定位
Vera 是面向金融行业的可信 AI Research Runtime，通过 Trust Gate 管理 AI 的证据来源、有效性和使用边界，让企业能够安全地将 AI 引入高价值研究流程。

### 为什么做这个(Founder Story)
金融行业每天产生大量研究任务，但 AI 在高风险决策场景中面临最大的障碍不是生成能力，而是可信问题。研究人员需要知道：数据来自哪里？是否最新？结论是否超出了证据范围？Vera 的目标不是让 AI 替代研究员，而是建立一套让金融机构敢于使用 AI 的可信基础设施。

### 解决的问题
AI 已经能回答大多数问题，但金融行业还不敢相信它——**幻觉不是准确率问题，而是信任成本问题**。错行情、错研报、错引用、错来源，任何一条都可能导致错误决策与资金损失。

行业困境是三重的:
- **风险**: AI 输出难以证明，数据来源无法追溯，缺少审计证据链
- **时间**: 研报/公告/新闻/数据源爆炸，机会转瞬即逝，人力无法规模化
- **成本**: 专业数据采购贵，人工尽调周期长，同样问题反复查

结论:**行业需要 AI 的效率，但不敢用 AI 做决策。**

### Vera 的答案
**不消除幻觉，管理幻觉。在不知道的时候，诚实地说不知道。**

Vera 交付的不是"答案"，而是**可核验的研究成果**:
- **KNOW** 懂金融业务——理解研究目标、行业语境与交付标准
- **DO** 会完成研究——调度数据、模型与工作流
- **TRUST** 结果可验证——证据可追溯、过程可审计、边界可声明

### 目标用户
- **财富业务**: 财富经理(解决"想用 AI 又怕失控")
- **机构研究**: 券商/买方研究员(解决"效率提升与研究可信")

### 当前状态
Finance Suite 已完成真实业务环境验证，支持金融研究流程自动化(touziagent.com)。核心架构 Trust Gate / Research Runtime / Company Panorama 已实现，与华福证券(同舟系统)合作验证中。

## 2️⃣ 技术介绍 (Technical Introduction)

### 不是 AI Wrapper，是可信治理层

Vera 不只是调用大模型生成内容，而是在模型调用之前和之后建立可信治理层，让 AI 在金融场景中具备可验证、可审计、可控制的运行能力。

大多数 AI 项目的路径：`Data → Prompt → LLM → Output`

Vera 的路径：
```
Data
  ↓
Evidence（来源验证 + 时间戳 + 可信等级标记）
  ↓
Trust Gate（证据准入 + 使用边界判定）
  ↓
Research Runtime（状态机调度 + 多模型协作）
  ↓
LLM（仅在证据充分时进入推理）
  ↓
QC（完整性评分 + 异常检测）
  ↓
Audit（每条结论关联 evidence_id）
```

这是基础设施差异，不是功能差异。

### 核心创新: Trust Gate(可信闸门)
**不是回答后提示风险,而是在回答前控制回答边界。**

所有证据先经过可信检查,再决定 AI 能回答什么。四种回答模式由证据质量自动选择:
- ✅ **可信分析**(Real): 真实生产数据,可深入分析
- ⚠️ **基础回答**(Fallback): 数据不足,仅提供事实说明
- 🧪 **演示模式**(Mock): 测试数据,仅展示功能
- ⛔ **拒绝回答**(Blocked): 超出可信边界,不进入推理

例: "现在可以买这只股票吗?" → 拒绝交易/仓位建议,但允许估值、行业、年报分析。

> 可信,不是 AI 更敢说,而是它知道什么时候不能说。

### 研究引擎: Research Runtime(7 状态机)
Vera = 研究员 · 状态机驱动,每步可解释、可中断、可证伪:
1. **PLAN** 规划——列提纲/拆问题
2. **RETRIEVE** 检索——四层数据降级:万得 → Tushare → 聚宽 → 东方财富
3. **BUILD_CTX** 证据组装——证据包组装 + 阻断字段剥离
4. **ANALYZE** 分析——财务对比 + 估值计算
5. **QC** 质量校验——完整性评分(completeness)+ 异常检测
6. **SYNTHESIZE** 报告生成——11 章节结构化报告
7. **DONE** 完成——每条结论关联证据编号(evidence_id)

> 数据 → 分析 → 验证 → 报告,一分钟完成。估值先行,理由跟上,跨源验证。

### 整体架构(6 层证据链)
```
用户入口   微信 / 飞书 / 企业微信 / 网页端
    ↓
Vera Agent  意图识别 · Skill 路由 · 工作流编排
    ↓
业务能力    Morning Brief · Company Panorama · Deep Research · 尽调 · 会议纪要
    ↓
研究引擎    任务拆解 · Provider 调度 · 状态机 · 重试/降级 · 多模型协作
    ↓
证据层      行情 · 财务 · 新闻 · 研报 · 引用 · 时间戳 · 来源追溯
    ↓
结果交付    LLM 分析与报告组装 · 可信研报 · 风险提示 · 能力声明
```
**贯穿其中的 Trust Gate**: 身份标记(REAL/FALLBACK/MOCK) · Prompt 准入(QC/Allowed/Blocked) · 执行治理(降级/隔离) · 输出边界(引用/声明)

### 技术栈
- **Backend**: Python (FastAPI) / Node.js
- **Frontend**: Vue.js / HTML5
- **Data**: 多 Provider 聚合(Wind / Tushare / JoinQuant / 东方财富 / AkShare)+ 容错降级
- **AI**: Claude API + 自研 Trust Gate 治理层
- **入口**: 微信 / 飞书 / 企业微信 / Web

### 为什么 AWS 是必要底座(不只是"使用云资源")

金融 AI 的核心挑战不是单次模型调用，而是**长期运行的研究工作流**。Vera 需要处理多源数据采集、证据生命周期管理、模型推理、审计记录和企业级部署，因此需要具备弹性计算、数据治理和全球部署能力的云基础设施。

具体来说，Vera 的每一层架构都对应一个无法绕开的云原生需求：

| Vera 架构层 | 为什么必须上云 | AWS 能力 |
|---|---|---|
| Vera Agent / 多模型协作 | 多模型按成本/质量动态切换，单机无法弹性调度 | **Amazon Bedrock**——统一接口，按需切换模型 |
| Research Runtime | 盘前集中触发、研究任务突发弹性，常驻服务成本不可接受 | **ECS/Fargate**——任务结束即释放，无空跑成本 |
| 证据层 / 多 Provider 聚合 | 证据包需长期存储与可追溯查询，本地存储无审计能力 | **S3 + Athena**——持久化 + 可追溯按需查询 |
| Trust Gate / 证据可审计 | 港/新持牌金融机构要求数据主权 + 操作审计留痕 | **区域化部署 + CloudTrail**——合规区 + 不可篡改审计日志 |
| 出海全球分发 | 英文界面面向港/新/东南亚，内地源站延迟不可接受 | **CloudFront**——边缘加速，用户体验与合规隔离 |

**核心论点**: Vera 需要的不是更多算力，而是一套能承载"可信治理"的合规云底座。Trust Gate 的"证据可审计"与 AWS CloudTrail 的"操作不可篡改"在设计哲学上同构——这不是凑合，是架构级契合。

## 3️⃣ 出海策略 (Global Market Potential)

**出海不是目的地，是可信能力的复制路径。**

```
中国金融研究场景验证
        ↓
  香港金融机构试点
  (券商 · 家族办公室 · 资产管理机构)
        ↓
  新加坡区域复制
  (东南亚金融机构 · 英文市场)
        ↓
Global Financial AI Infrastructure
```

**为什么这个路径可信:**

- **中国(已验证)**: 真实金融研究场景中打磨 Trust Gate 和 Research Runtime，形成可复制的能力底座
- **香港(第一步)**: 中国金融机构的天然出海窗口，监管框架相对成熟，券商/资管/家办对 AI 研究工具需求强，且对"可审计"有明确监管要求 — 正好是 Trust Gate 的强项
- **新加坡(区域复制)**: 东南亚金融中心，英文市场，区域性金融机构集中，Trust Gate 的可信架构适配英语世界对 AI 的更高合规要求
- **全球(长期)**: Trust Gate 作为金融 AI 可信运行标准向更多市场授权输出

**AWS 的角色**: 港/新合规区域化部署 + CloudFront 全球分发，是这条路径的基础设施保障，不是可选项。
