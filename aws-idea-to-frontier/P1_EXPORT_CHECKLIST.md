## A. PDF 路演导出 + Claim Audit

**目的**: 不只是查排版，而是做一次 Claim 边界审查

### 步骤 1: 导出 PDF
- SSOT: `/Users/Zhuanz/finance-suite/roadshow-2026-06/html/index.html`
- 导出方式: Chrome 打印 → 另存为 PDF（或 headless Chrome，见 `reference_brief_export_workflow`）
- 检查: 14 页全部输出，无缺页、无图片断链、字体无乱码

### 步骤 2: Claim Audit（逐页对照）

对每一页内容，按下表套级别：

| 级别 | 定义 | 允许出现在 PDF |
|---|---|---|
| Declared | 架构/设计层面有文档 | ✅ |
| Documented | 有具体实现文档/代码 | ✅ |
| Implemented | 有可运行的本地实现 | ✅（标注"本地验证"） |
| Runtime Proven | 真实流量跑通 | ✅（如有则标注） |
| Production Proven | 生产环境 + 真实用户 | ⚠️ 有证据才用，否则不写 |

**重点盯住的措辞**（这些在 PPT 里如果出现，逐个确认语境）:

| 措辞 | 风险 | 处理 |
|---|---|---|
| "数字员工" | 可能被理解为已大规模部署 | 确认语境是愿景/roadmap，还是当前状态 |
| "金融机构使用" | 暗示已有机构客户 | 收敛为"合作验证中"或删除 |
| "行业标准" | 暗示已被行业认可 | 只有 Trust Gate 可以讲"面向行业标准设计"，不说"已成为标准" |
| "已服务大量用户" | 无数据支撑 | 删除或改"面向金融从业者" |
| "已被券商采用" | 无公开合同 | 改"与券商合作验证中" |
| 任何具体%数字 | 需引用来源 | 有来源留，没来源改定性表述 |
