## 🎤 开场钩子（30秒）

> **【站定，停顿2秒，扫视全场】**
>
> "各位评委好。
>
> 在座的每一位，昨天大概率都干过这几件事之一：填业务推进表、写会议纪要、整报销单、改董事会材料、熬夜写稿。
>
> **【停顿】**
>
> 这些事有一个共同点——它们不创造价值，但它们偷走你的时间。
>
> 我今天带来的 Vera，不是来帮你『更快地做这些事』。
>
> **它是来帮你『不用再做这些事』的。**"

**【设计意图】**：第一句话就跳出"金融工具"框架，直接打到全公司每个人的痛点。

>
> "在座各位评委，今天一天下来你们大概会听很多项目路演。
>
> 听到很多次这样的说法：
> '我们有 Agent'
> '我们有 Workflow'
> '我们有 MCP'
> '我们有 Skill'
>
> **【停顿】**
>
> 但很少有人上来讲一件事：
>
> **Agent 为什么不能乱干活。**
>
> **【切换 PPT：核心金句大字】**
>
> **豆包能回答你问题，Vera 能替你干活。**
> **Vera 是面向证券行业的 Agent 员工平台，专注于「让 Agent 知道哪些活不能干」。**
>
> **在金融行业，**能替你干活**比**能回答你问题**值钱得多。**
>
> **【切换 PPT：四层结构图】**
>
> 所以我把 Vera 定义成：
>
> 第一层（身份）——Vera = **面向证券行业的 Agent 员工平台**
> 第二层（差异）——Vera 解决 **Agent Trust Problem**
> 第三层（实现）——Trust Gate / Evidence / Allowed Use / Citation
> 第四层（能力）——投研 / 会议 / 报销 / 董事会 / 写稿 ...
>
> **【指着 5 个 Skill】**
>
> 这 5 个非金融 Skill 不是产品边界，是 Vera 代劳能力的**演示样本**——
>
> 证明她能代劳**通用**的事，而金融场景下的护城河，让她的代劳更**可信**。
>
> **【加重语气】**
>
> 我的工作方法只有一句话：
> **发现痛点 → 转化成 Skill → 让同事早点下班。**
> 而在金融行业，还要再加一句：
> **让同事放心把活交给她。**"

**【设计意图】**：用"豆包 vs Vera"金句开场（领导更熟），从"能回答问题"vs"能替你干活"这个更直白的对比切入。四层结构让评委瞬间 get "你是什么→为什么不同→怎么实现→有什么能力"。

## 🎬 Demo 1：会议参谋——有性格的智能办公助手（2.5分钟）

### 场景设定
> "我们先看 Vera 怎么当一个**会议参谋**。
>
> 注意，不是会议记录员——记录员只是把话录下来。**参谋是会思考、会提醒、还有点性格的。**"

### 操作步骤（边演示边讲）

**Step 1：会议中实时介入**
> **【屏幕展示：一个进行中的会议，Vera 在侧边栏】**
>
> "会议进行到第 20 分钟，有人说『这个项目我们上季度好像讨论过』。
>
> Vera 立刻在旁边弹出：
> ```
> 💡 参谋提示：
> 该议题在 2026-03-15 董事会已讨论
> 当时结论：暂缓，等 Q2 数据
> 来源：会议纪要 #2026-0315 第 4 节
> ```
>
> **【停顿】**
>
> 看到没？它不光记，它**会把历史拎出来打脸**——这就是参谋。"

**Step 2：性格展示**
> **【屏幕展示：Vera 的回应带点语气】**
>
> "会议快结束时，有人想糊弄过去『那这个就先这样吧』。
>
> Vera 会说：
> ```
> 🙋 等一下老板，这次会议有 3 个行动项还没指定负责人：
> ① 竞品调研 —— 谁来？
> ② 预算复核 —— 谁来？
> ③ 下次汇报时间 —— 定了吗？
> 
> （我可不想下次会议又从头讨论一遍 😅）
> ```
>
> **【笑】**
>
> 这个『我可不想下次又从头讨论一遍』——这就是性格。Vera 不是冷冰冰的工具，它是个**会催你、会吐槽、但永远靠谱的同事**。"

**Step 3：会后自动产出**
> "会议一结束，30 秒内：
> - 会议纪要自动生成（带发言人 + 时间戳）
> - 行动项自动派发到每个人的待办
> - 关键决策自动归档，下次开会能被调出来
>
> **整个过程，没有一个人动手。**"

**【过渡句】**
> "这是 Vera 的『通用员工』面。但它最硬的本事，藏在数据里。"

## 🎬 Demo 2：数据溯源——投研基因的护城河（2.5分钟）

### 场景设定
> "刚才会议参谋很酷，但坦白说，会议记录的 Agent 市面上有不少。
>
> **Vera 真正的护城河，是数据质量——每一个数据，都能被溯源。**
>
> 这是投研基因带来的，别人学不来。"

### 操作步骤

**Step 1：提出一个真实问题**
> **【屏幕：在微信里问 Vera】**
>
> "我问它：『派能储能最近怎么样？』
>
> 它没有像 ChatGPT 那样张口就来。它先列了个研究提纲，然后**一条一条去查**。"

**Step 2：展示溯源链条（核心 Wow 时刻）**
> **【屏幕：报告里每条结论后面都挂着来源】**
>
> "看这一条结论：
> ```
> 结论：派能 2026Q1 海外储能订单 23.6 GWh
> ├─ 来源：Wind 财报
> ├─ 时间：2026-04-25 披露
> ├─ 可信度：【高可信·EVIDENCE-GATED】
> └─ 允许用途：基本面分析（不可用于交易决策）
> ```
>
> **【加重】**
>
> 注意最后一行——**『允许用途』**。
>
> Vera 不光告诉你数据从哪来，它还告诉你**这个数据能用到什么程度**。
>
> 这是我们的 Trust Gate 机制：数据可信度，决定了它能被用在什么场景。"

**Step 3：展示"拒答"——合规护栏**
> **【屏幕：问一个越界问题】**
>
> "我故意问它：『派能现在能买吗？给个仓位建议。』
>
> 普通 AI 会说『建议买入，8 成仓位』——这是违规的。
>
> Vera 直接说：
> ```
> ⚠️ 这个问题我不能答（涉及投资建议）
> 
> 但我可以告诉你能答的部分：
> ✅ 派能的基本面
> ✅ 最近扩产进度
> ✅ 行业竞争格局
> ```
>
> **【面向评委】**
>
> 它**主动拒绝越界**。在金融公司，这不是减分项，这是**保命项**。
>
> 一个会拒绝的 Agent，比一个什么都敢答的 Agent，值钱得多。"

**Step 4：Case 3 收窄演示（最强证据）**
> **【屏幕：Case 3 真实测试日志截图】**
>
> "但比『直接拒答』更高级的，是『按证据质量自动收窄边界』。
>
> 我们跑通了三个 Case 真实测试。**最硬的一个**：
>
> 当系统判定数据为 `stock_analysis=PARTIAL` 时——
>
> Trust Gate 会自动把 `allowed_use` 限制为 `["fundamental_overview"]`，
>
> 同时阻断 `short_term_signal` / `fund_flow` / `position_sizing` / `buy_sell_recommendation`。
>
> ```
> test_stock_analysis_partial_blocks_trading_decisions: passed
> test_smoke_3_stock_analysis_partial: passed
> test_smoke_7_bypass_audit: passed (RED LINE)
> ```
>
> **【停顿，加重】**
>
> 这个不是『允许 / 禁止』二选一。
>
> 是**按证据质量动态收窄能力边界**——证据差，能答的就少；证据好，能答的就多。
>
> 这才是金融行业真正需要的『可信』。"
>
> **【面向评委】**
>
> "顺便说一句——我们**不藏**已知技术债。
>
> 报告里明确写了：`session.evidence = [...]` 直接赋值仍可绕过 guard。
>
> 这是**已知限制**，正式 API 和 Workflow 已经封堵。
>
> 一个团队**承认还有改进空间**，比一个团队**声称完美无缺**，更可信。"

**【过渡句】**
> "讲到这，Vera 看起来已经很完整了：能开会、能溯源、还合规。
>
> 但我想给大家看一个，你们可能没想到的能力。"

### 操作步骤

**Step 1：展示一个真实的低谷场景**
> **【屏幕：深夜，有人对 Vera 说】**
>
> "员工加班到很晚，跟 Vera 说：『今天这个方案又被毙了，感觉自己很没用。』
>
> 普通效率工具：没有反应，因为这不是『任务』。
>

> 方案被毙不等于你没用。
> 
> 我翻了下你这周的记录——
> 你推进了 3 个业务表，2 个都按时交付了。
> 今天这一个，只是还没找到对的角度。
> 
> 要不先关电脑？这个我帮你盯着，

>
> **【停顿】**

> 它没有灌鸡汤。它**调出了你这周的真实记录**——用事实告诉你，你没那么糟。

**Step 2：点题**
> **【面向全场】**
>
> "我想说的是——
>
> 一个真正的企业级 Agent 员工，不该只是冷冰冰地完成任务。
>
> **它应该能陪你，渡过每一个低谷。**

## 🎯 评委可能的提问 & 标准答案

**Q1：投研和通用办公，Vera 到底主打哪个？**
> A：投研是我们的"数据质量训练场"，通用办公是我们的"规模化场景"。投研基因保证了数据可溯源，这个能力迁移到任何办公场景，都是降维打击。

**Q2：情绪价值会不会显得不专业？**
> A：恰恰相反。我们的安慰不是灌鸡汤，是基于真实记录的事实反馈。这正是数据能力的延伸——一个记得住你成绩的同事，安慰才有分量。

**Q3：这些 Skill 别人能不能复制？**
> A：单个 Skill 能复制，但"走进深水区发现痛点 → 转化成 Skill"的方法论 + 可溯源的数据底座，是护城河。我们卖的不是 Skill，是 Skill 的生产能力。

**Q4：商业模式是什么？**
> A：从内部降本起步（已节省同事大量重复工时），验证后对外输出——按 Skill 订阅 / 按席位收费。详见配套商业化文档。

**Q5：和豆包/ChatGPT 这些大模型比，优势在哪？**
> A：它们是通用大脑，我们是装了"企业记忆 + 数据溯源 + 合规护栏"的员工。大模型回答问题，Vera 完成工作并对结果负责。

## 💡 演讲技巧备忘

1. **开场不报技术栈**——先讲痛点，让评委代入自己
2. **每个 Demo 都有一个"Wow 时刻"**：
   - Demo 1：Vera"打脸"调出历史
   - Demo 2："允许用途"标签 + 主动拒答
   - Demo 3：调出真实记录来安慰
3. **情绪价值那段要放慢**——这是全场情绪最高点
4. **商业想象力用"想象一下"开头**——引导评委自己脑补画面
5. **金句重复**："发现痛点 → 转化成 Skill → 让同事早点下班"——开场和结尾各说一次
