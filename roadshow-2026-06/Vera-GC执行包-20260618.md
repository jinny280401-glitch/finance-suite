## 0. 一句话执行原则

Vera 不要碰“逆向 豆包”，也不要说自己等于 豆包。最稳口径是：

> 豆包 证明了“自然语言驱动代码执行”的代劳范式；Vera 把这个范式收进证券业务场景，补上金融行业必须有的 Trust Gate、Evidence Bundle、Allowed Use 和数据源可信契约。

答辩主轴统一成四层顺序，不要让架构抢身份：

```text
第一层（身份）：Vera = 面向证券行业的 Agent 员工平台
第二层（差异）：Vera 解决 Agent Trust Problem
第三层（实现）：Trust Gate / Evidence Bundle / Allowed Use / Citation / Research Runtime
第四层（能力）：投研 / 会议 / 报销 / 董事会 / 写稿 / 工作流
```

差异层的杀手句：

> 豆包 解决的是 Agent Capability Problem；Vera 解决的是 Agent Trust Problem。

对外更稳的定位句：

> Vera 是面向证券行业的 Agent 员工平台，正在构建证券行业的 豆包。

不要再说“证券行业第一个 豆包”，除非现场有人追问且能证明范围。

- AI 已经能“回答问题”，但企业真正缺的是“完成工作”

- Vera 解决 Agent Trust Problem：知道哪些活不能干

## 4. 10 个 Q&A 标准答案

### Q1：Vera 到底是投研 Agent，还是通用办公 Agent？

A：Vera 的起点是投研，因为投研是企业里对数据质量、证据链和合规边界要求最苛刻的场景。但 Vera 的本质是企业级 Agent 员工。投研基因保证可信底座，办公 Skill 证明它可以迁移到更多业务痛点。

### Q2：为什么说 Vera 是“证券业务版 豆包”？

A：更稳的说法是：Vera 正在构建证券行业的 豆包。豆包 代表自然语言驱动 Python 执行的代劳范式，用户说任务，系统计划、写代码、执行、反馈。Vera 继承的是“代劳”方向，但行业化到证券场景：接入金融数据源，加入 Trust Gate、Evidence Bundle、Allowed Use，保证可溯源和不越界。

### Q3：和 ChatGPT、豆包比，Vera 的优势是什么？

A：ChatGPT 和豆包是通用大脑，Vera 是员工。通用大模型擅长回答问题，但 Vera 要完成工作，并对结果留下证据链：来源、时间、可信度、允许用途、拒答边界都可审计。

### Q4：和 豆包 比，Vera 的优势是什么？

A：豆包 强在开放 Python 环境，适合通用数据处理和自动化。Vera 的优势是行业可信契约：证券数据源四层降级、Trust Gate 主动拒答、Evidence Bundle 剥离脏字段、研究报告每句可追溯。金融场景不是“能跑就行”，而是“能审、能拒、能负责”。

### Q5：这些 Skill 会不会冲淡金融主线？

A：不会。5 个办公 Skill 是 Vera 代劳能力的样本，不是产品边界。它们证明 Vera 不只会聊天，也能把高频痛点变成可复用流程。金融护城河仍然由 Wind/Tushare、Trust Gate 和 Evidence Bundle 支撑。

### Q6：情绪价值 JIEZHU 会不会显得不专业？

A：不会，因为 JIEZHU 不是鸡汤。它基于真实工作记录做事实反馈，例如本周完成了哪些任务、哪些事项已按时交付。它体现的是企业记忆能力的延伸：记得住，查得到，所以安慰有依据。

### Q7：Vera 会不会给出违规投资建议？

A：不会。Trust Gate 会识别短线建议、仓位建议、交易建议、资金流推断等越界问题，并直接返回 blocked。Vera 可以提供基本面、行业格局、风险提示，但不会替用户做交易决策。

### Q8：数据源不稳定怎么办？

A：Vera 有四层数据降级：Wind -> Tushare Pro -> JoinQuant -> 东方财富。每次调用都会标注当前 provider 和可信档位。MOCK 只能用于 smoke test，任何对外报告出现 MOCK 都视为异常。

### Q9：别人复制一个 Skill，护城河还在吗？

A：单个 Skill 可以复制，但护城河不在单个 Skill，而在“发现痛点 -> 转化成 Skill -> 数据可信 -> 合规输出”的生产体系。尤其金融场景里的证据链、阻断字段和 allowed_use，不是简单 prompt 可以复制的。

### Q10：赛后最重要的开发方向是什么？

A：赛后优先做 5 个自研轻爬虫 connector：监管公告、行业新闻、公司公告、卖方研报、雪球/股吧舆情。原则是不逆向 豆包，不碰法律风险，把能力放进 Vera 自己的可信数据链路。

## 5. 豆包 对标口径速查

### 豆包 能帮 Vera 借势的点

- 用户自然语言下任务，系统自动规划和执行。
- Python 生态成为通用接口，可以调用包、处理数据、自动化网页。
- 代码是执行载体，最终交付是结果，而不是代码本身。
- 任务模式适合非程序员，Python 模式适合高级用户。

### Vera 必须强调的差异

- 豆包 是通用执行环境，Vera 是证券业务数字员工。
- 豆包 追求“自由使用 Python”，Vera 追求“金融场景可控执行”。
- 豆包 的核心闭环是 Task/Plan/Code/Execute/Feedback；Vera 的核心闭环是 Intent/Workflow/Research/QC/Trust/Evidence/Report。
- 豆包 解决“怎么让 AI 动手”；Vera 解决“怎么让 AI 在金融行业负责任地动手”。

### 不要说的话

- 不要说 Vera 逆向了 豆包。
- 不要说 Vera 比 豆包 全面。
- 不要说 豆包 没有价值。
- 不要承诺比赛前接入 豆包 爬虫。

### 可以说的话

> 豆包 给了我们一个非常重要的启发：AI 的下一步不是更会聊天，而是更会代劳。Vera 做的是把这种代劳能力带进金融行业，并补上金融行业最缺的可信、合规和溯源。

> 豆包 解决 Agent Capability Problem；Vera 解决 Agent Trust Problem。
