## 一、项目说明（总览）

Vera 是面向**证券行业**的 Agent 员工平台。**豆包能回答你问题，Vera 能替你干活。**Vera 是面向证券行业的 Agent 员工平台，相比豆包等通用 AI 助手，Vera 解决的核心问题是「**让 Agent 知道哪些活不能干**」（Agent Trust Problem）——在金融行业，后者往往比前者更重要。

Vera v2.0 阶段将底层架构从「工具集合+数据源+生成结果」升级为「**Intent Layer → Workflow Runtime → Research Runtime → QC → Trust Gate → Evidence Bundle → Report Assembly**」的研究操作系统，拆分为 7 个功能模块。**投研只是第一个成熟的 Skill**——业务推进表/报销/会议记录/董事会/写稿等 5 个非金融 Skill 已经在跑，证明 Vera 的代劳能力是通用的；而金融场景下的 Trust Gate / Evidence / Allowed Use / Citation 护城河，是她相对通用 Agent 平台最容易建立差异化的位置。

**核心护城河**：Trust Gate 三档可信契约 + Evidence Bundle 阻断字段机制 + Citation 强制挂载，确保每个研究结论可追溯到证据、数据源、时间戳与允许用途（Allowed Use），从根本上解决 AI 幻觉与合规越界两大行业痛点。

**量化验证**：已完成 Research Runtime v0.8 smoke 全通过（5/5）、Trust Gate Contract v0 冻结、多渠道路由延迟 < 500ms、视频研报拆解准确率 94%。

## 二、场景痛点分析

### 投研人员面临的三大核心痛点

**痛点 1：数据源不稳定 → 单点故障即断服务**
- 现状：Wind API 故障频率约 2-3 次/月，每次故障导致 30-120 分钟服务中断
- 影响：投研团队需人工切换数据源，盘中关键时段（9:30-11:30、13:00-15:00）切换成本极高
- 用户反馈："早盘集合竞价最需要数据的时候，Wind 挂了就只能干等"

**痛点 2：盘中信息过载 → 人工整理难以 7×24**
- 现状：单个投研人员平均监控 50-80 只自选股，每日需处理：
  - 实时行情数据（分钟级）
  - 公司公告（日均 10-15 条/股）
  - 卖方研报（日均 3-5 篇相关研报）
  - 行业新闻（日均 20+ 条）
- 影响：人工整理耗时 2-3 小时/天，且易遗漏关键信息
- 用户反馈："晚上看到重要研报第二天才知道，机会已经错过了"

**痛点 3：合规边界模糊 → AI 越界回答担责风险**
- 现状：ChatGPT/Claude 等通用 AI 会直接回答"能不能买、仓位多少、目标价"等越界问题
- 影响：违反证券从业合规要求，一旦客户依据 AI 建议交易亏损，存在法律风险
- 监管要求：《证券投资顾问业务暂行规定》明确禁止未持牌人员提供投资建议
- 用户反馈："用 ChatGPT 查股票，它敢说'建议买入'，我不敢给客户转发"

### 现有方案的三大缺陷

| 方案类型 | 代表产品 | 核心缺陷 | 成本 |
|---------|---------|---------|------|

## 三、技术实现路径与方法

### 3.1 整体架构：七层研究操作系统

```
用户需求
    ↓
① Intent Layer（意图识别）
    ↓
② Workflow Runtime（工作流编排）
    ↓
③ Research Runtime（研究引擎）
    ↓
④ QC Layer（质量检测）
    ↓
⑤ Trust Gate（可信网关）
    ↓
⑥ Evidence Bundle（证据包）
    ↓
⑦ Report Assembly（报告生成）
```

### 3.2 核心技术模块详解

**模块 1：Intent Layer — 智能意图路由**
- 技术方案：基于 NLU 的 8 类意图分类器
- 支持意图：个股研究 / 市场脉搏 / 集合竞价 / 科技早盘 / 深度研究 / 板块热度 / 新闻解读 / 视频拆解
- 创新点：路由过程写入 `routing_reasoning` + `routing_evidence`，任何错配可复盘
- 对比：通用 AI 无意图路由，"科技早盘"会被误识别为个股查询

**模块 2：Research Runtime — 状态机驱动研究引擎**
- 技术方案：8 阶段状态机（INIT → PLAN → RETRIEVE → BUILD_CONTEXT → ANALYZE → QC → SYNTHESIZE → DONE）
- 数据结构：Section QC（每章节独立质检）+ Evidence Bundle（原始响应经 `_strip_blocked_fields` 处理）
- 创新点：告别单次 prompt 直出，引入可追溯的研究链路
- 对比：ChatGPT 是一次性生成，无法追溯中间步骤

**模块 3：Trust Gate — 三档可信契约**

| Provider 类别 | Trust Status | 允许使用场景 | 典型数据源 |
|--------------|-------------|-------------|-----------|
| PRODUCTION | passed | overview / analysis / production_research | Wind、Tushare Pro |
| FALLBACK | passed | overview（基本面速览） | JoinQuant、东方财富 |
| MOCK | passed | smoke test only | 仅测试环境 |

**强制阻断机制**：
- 禁止行为：短线建议 / 资金流推断 / 仓位建议 / 交易建议
- 阻断字段：`_qc` / `raw` / `payload` 不得进入 LLM 上下文
- 拒绝路径：`missing_source` 或 `missing_content` 直接返回 `blocked`

> 📊 **【图2位置】** 待插入：Trust Gate Contract Flow（指令见 ASCII架构图指令-v2.md）

**模块 4：Finance Data Gateway — 四层数据降级**

```
Wind API（首选）
    ↓ 故障自动降级（< 500ms）
Tushare Pro（备选1）
    ↓
JoinQuant（备选2）
    ↓
东方财富（备选3）
```

- 技术指标：99.9% 数据可用性（实测 30 天）
- 显式标注：每次调用返回 `_qc.fallback_source` 字段，标明当前档位
- 创新点：告别"有返回结果 = 能力完成"的虚假对齐

**模块 5：External Intelligence — 年报季报验证引擎**

基于 G 方法论的三段式验证：

```
Field 抽取 → Rule 套用 → Verdict 产出
   ↓            ↓           ↓
年报/季报   确定性规则    可证伪结论
关键字段   (不依赖LLM)   (带证据追溯)
```

- 数据源：年报 / 季报 / 招股说明书 / 重大事项公告（A股 + 港股 + 美股）
- 典型应用：
  - 沐邦（2025年报）：玩具 + 光伏跨界业务拆分
  - 派能（2026一季报）：储能扩产进度验证
  - 北方华创（2025年报）：半导体设备产业链
- 创新点：cross-case 锚点，同一 rule 横向比较不同公司年报

**模块 6：多端触达 — 全渠道路由网关**
- 技术方案：OpenClaw 统一路由层
- 支持渠道：微信 / 飞书 / 企微 / Web
- 性能指标：路由延迟 < 500ms（P99）

**模块 7：自动化助手体系**
- 晨会助手：集合竞价扫描 + 科技早盘 + 市场温度扫描
- 自选股监控：价格提醒 + 异动提醒 + 资金变化（已触发 247 次）
- 内容助手：视频拆解（YouTube/B站，准确率 94%）+ 新闻聚合（7x24）+ 研报摘要

## 四、核心创新点阐述

### 创新点 1：研究 OS 而非工具集合

**对比维度** | **通用 AI（ChatGPT/豆包）** | **Vera Agent v2.0**
---|---|---
生成方式 | 单次 prompt 直出 | 状态机驱动（8 阶段可追溯）
研究结构 | 无结构化章节 | 11 章节标准化报告
质检机制 | 无 | Section QC + Evidence Bundle
证据追溯 | 无法追溯 | 每条结论挂 evidence_id
**核心差异** | **让 Agent 能干活** | **让 Agent 知道哪些活不能干**

**价值**：从"一次性对话"升级为"可追溯研究流程"，符合投研团队的专业工作习惯。**更强的 Agent 满街都是；更可信的 Agent，是金融行业刚需。**

### 创新点 2：Trust Gate 三档契约

**行业痛点**：通用 AI 会随口给出"建议买入""8 成仓位"等越界建议，存在合规风险。

**Vera 的解决方案**：
1. **主动拒答机制**：识别到越界问题（仓位/交易建议）直接返回 `blocked`
2. **三档可信契约**：PRODUCTION / FALLBACK / MOCK 显式标注，数据可信度决定 allowed_use
3. **阻断字段强制剥离**：`_qc` / `raw` / `payload` 不得进入 LLM 推理链路

**对标葱花投研**：葱花用 NAV/FCFF/DDM 三层估值方法标注专业度，Vera 用 Trust Gate 三档契约标注可信度。

### 创新点 3：Evidence Bundle 阻断字段

**技术细节**：
- 在 Evidence Bundle 阶段，原始 Gateway 响应经过 `_strip_blocked_fields` 处理
- 阻断字段：`_qc`（质检元数据）、`raw`（原始响应）、`payload`（未清洗数据）
- 只有清洗后的结构化字段才能进入 LLM 上下文

**护城河价值**：这是其他 AI Agent 不具备的能力，确保 LLM 不会"看到"原始脏数据，从根本上降低幻觉风险。

### 创新点 4：Methodology Consumer 角色（Serenity）

**与 Provider Runtime 的本质区别**：
- **Provider Runtime**：实时行情 + 财务快照（颗粒度到日频）
- **External Intelligence**：报告期切片（颗粒度到季度）

**G 方法论三段式**：
1. **Field 抽取**：从年报"管理层讨论""主营业务"抽取结构化字段
2. **Rule 套用**：用确定性规则判断（如客户集中度 > 60% → flag 供应链风险）
3. **Verdict 产出**：不依赖 LLM，输出可证伪结论

**案例**：派能 2026 一季报 → 抽取"在建工程 vs 玩具营收" → 判定"光伏在建烧钱" → 回到年报 P.42 / 第 6 节 / 表 3。

### 创新点 5：REAL/FALLBACK/MOCK 显式标注

**行业虚假对齐问题**：很多 AI 产品宣称"已接入 12 个数据源"，实际上只是"有返回结果"，但没标注数据来源档位。

**Vera 的透明化策略**：
- 每次 Provider 调用返回 `_qc.fallback_source` 字段
- MOCK 数据仅出现在 smoke test，任何对外报告出现 MOCK 即视为异常
- 对比：通用 AI 是黑盒，用户无法判断数据来源可信度

### 6.2 客户记忆隔离

**技术方案**：基于 `customer_id` 分片
- 不同用户的数据存储在独立分片
- 跨用户数据严格隔离，禁止跨片查询
- 客户删除账号时，相关数据物理删除（GDPR 合规）

### 6.3 Trust Gate 主动拒绝越界请求

**禁止回答的问题类型**：
- 短线建议："明天会涨吗？"
- 仓位建议："建议配置多少仓位？"
- 交易建议："现在可以买入吗？"
- 资金流推断："主力资金在出逃？"

**技术实现**：Trust Gate 在 Evidence Bundle 阶段识别越界请求，直接返回 `blocked` 状态，不依赖 LLM 自律。

**法律依据**：
- 《证券投资顾问业务暂行规定》（证监会公告 [2010] 27 号）
- 《证券经营机构投资者适当性管理实施指引（试行）》

### 6.4 阻断字段机制

**强制剥离字段**：
- `_qc`：质检元数据（completeness、stale_data、missing_dimensions）
- `raw`：原始 API 响应（未清洗数据）
- `payload`：中间态数据结构

**实现方式**：在 Evidence Bundle 阶段通过 `_strip_blocked_fields` 函数强制剥离，技术上确保这些字段无法进入 LLM 推理上下文。

### 6.5 免责声明

Vera 的输出**仅供研究参考**，不构成任何证券、基金、期货、外汇或其他金融产品的投资建议。投资者在做出投资决策前，需：
1. 结合自身风险承受能力
2. 进行独立的尽职调查
3. 必要时咨询持牌投资顾问
4. 交易前进行人工复核
