## 1. 执行摘要

**Vera 是一个把"AI 研究"从答案变成"证据"的轻量化金融研究助手**——由单人创业团队运营，借助自研的多领域 AI 智能体协同工作。

我们相信：在 AI Agent 时代，单人能完成过去需要小型机构的研究工作量，但**这种"准机构级"产出的可信度不能靠输出量堆，必须靠治理层**。这就是 Vera 做的事：**Trust Gate（信任门）**——每条结论都必须穿过"数据源 → QC → 审计 → 输出"四道关，每个事实都自带证据 ID，用户可点击直接抵达原始数据。

OPC 专项赛鼓励的方向正是"以 AI 智能体、数字工具、云端协同实现'单人成军'的轻量化创业"。Vera 与这个方向同构。我们期待借助青创杯平台、海珠区 AI 资源，以及广州对一人公司的政策托举，把"信任治理 + 单人创业"这件事做扎实。

## 2. 项目背景

### 2.1 行业已识别的关键挑战

生成式 AI 在金融研究场景的应用迅速扩张，但已识别的核心问题是模型幻觉：单条答案可能来源缺失、时点错位、或与原始数据偏离。行业主流研究工具和开源 Agent 框架普遍**未内置独立审计层**。本研究方向的痛点已形成共识，引用文献与公开行业讨论众多（具体数据点此处不引用未证实的统计数字）。

### 2.2 散户与中小机构对"可信研究"的需求

- 主动关注 A 股的散户/中小投资者需要的不只是 AI 答案，而是**可追溯**的回答。
- 对 AI 工具有研究伦理要求的高校、培训机构、地方金融从业者群体存在明显的供给缺口。
- 现有方案的两类折中：(a) 完全手动研究，时延高、覆盖窄；(b) 通用 AI 助手，没有审计层，结果无法复核。

### 2.3 单人创业窗口期

AI Agent 时代的工作流能被单人团队 + 多个领域专用智能体替代，这一窗口在过去 12 个月开始成型。OPC 合法化把"单人创业+轻资产"从自发形态变成合规形态。这两件事叠在一起，给"信任治理优先的单人创业"打开了空间。

---

## 3. 解决方案：Vera 的信任门（Trust Gate）

### 3.1 核心创新点

Vera 的差异化不是"做了 AI 助手"，而是**把治理层（Governance）做到产品背后**：

```
数据源 → Trust Gate 入口 → QC 校验 → 审计决策 → 输出渲染
                              ↓
                       Evidence Manifest
                  （每条结论带证据 ID + 来源时间戳）
```

每一句研究产出都必须：
1. 携带 **evidence_id**（定位到一份已被 Trust Gate 接受的事实）；
2. 携带 **provider / tier / qc_status**（信源真伪可考）；
3. 不出现 **target price / buy-sell signal / expected return**——这是治理层的硬约束，不是 prompt 工程。

### 3.2 与现有产品的差异

| 类型 | 输出形态 | 审计能力 |
|---|---|---|
| 通用 AI 助手 | 自然语言答案 | 无 |
| 传统研究 SaaS | 人工研究报告 | 人工复核 |
| **Vera** | AI 速度 + 每条结论可点回原始数据 | 治理层（Trust Gate）独立运行 |

差异不在 UI 层，在治理层。

### 3.3 智能体协同结构（轻量化）

Vera 的"团队"由多个领域专用智能体组成，各自拥有受限的 evidence scope：
- 市场情绪 / 估值 / 风险审计 / 报告组装 / 合规检查 / 用户交互

每个智能体不签保密协议，但**每条结论都有证据 ID**。这是"AI Agent 时代的单人公司"的现实形态：不是逃避治理，而是把治理做到位。

## 4. 商业模式

### 4.1 客户群体（三层，不宣称未验证的客户数）

- **散户/主动投资者**：希望 AI 助手但需要可追溯的研究结论；
- **中小机构/高校/培训机构**：对 AI 工具有研究伦理或合规要求；
- **计划嵌入合作的研究流**：与本地金融科技机构的合规研究接入（**计划中，尚未签约**）。

### 4.2 收入模式（轻量化路径）

OPC 强调"轻量化"。Vera 的成本结构与单一订阅 SaaS 模型匹配：

- **免费层**：基础市场情绪扫描与简版报告；
- **订阅层**：月费/季费，含完整 Trust Gate 输出与证据追溯；
- **增值层**：定制研究报告、机构嵌入（计划中）。

### 4.3 成本结构（单人成军优势）

- 主要可变成本：模型 API + 少量云存储 + 域名/服务运维；
- 固定成本接近于零：无办公室、无人力工资、**单人成军**；
- 这使单位经济模型在到达较小用户规模时即可转正，符合"轻量化创业"评审取向。

## 5. 团队

### 5.1 团队规模

Vera 由单人主导，借助自研 AI 智能体协同。这正是 OPC 字面意义：**一人公司 + AI 智能体 = 一夆公司**。

### 5.2 创始人能力

创始人同时承担技术、商业、合规设计三类职责。具体个人简历作为单独附件提交（包含年龄、学历、过往项目经验等参赛所需信息；本规划书不展开）。

### 5.3 "团队"延伸：AI 智能体

代替传统员工分工，Vera 由多个领域专用 AI 智能体组成（详见 §3.3）。每个智能体的产出都受到 Trust Gate 治理约束。这意味着"团队"的边界 = 可验证的 evidence scope 边界，而不是员工数量。

## 8. 风险与对策

### 8.1 数据与模型可靠性风险

- **风险**：LLM 不可消除幻觉。
- **对策**：Trust Gate 在输出前做最后一道关——任何不能溯源到 evidence_id 的结论被结构层降级或拒绝输出。三级降级：FULL → PARTIAL → STRUCTURAL。

### 8.2 合规与边界风险

- **风险**：AI 研究助手与"投资建议"边界模糊。
- **对策**：治理层硬约束——**不发目标价、不发买卖信号、不发预期收益**。所有数字输出都标注："基于公开数据的研究快照，不构成投资建议"。

### 8.3 资源单一风险

- **风险**：单人团队的可持续性。
- **对策**：阶段一不依赖外部资本，运营资金主要来自订阅收入滚动；阶段二根据现金流判断是否引入兼职合作伙伴。

## 9. 结语

Vera 不是在做一个 AI 研究产品，是在实践一种**AI 时代个人创业**的范式：

> **单人在 AI Agent 协同下，可以完成过去需要小型机构的研究工作量，并自带研究级的可审计性。**

这正是 OPC 鼓励的方向，也是海珠琶洲 AI 发展政策所支持的方向。

我们期待与青创杯评委、广州青年创新创业生态一起，把"单人创业 + 信任治理"这件事做扎实——先在 OPC 制度下活下来，再走到直通决赛的赛道上证明治理层的可规模化。
